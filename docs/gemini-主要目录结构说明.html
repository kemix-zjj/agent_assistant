1顶层目录

根目录只放 5 个主目录 + 2 个说明文件，任何业务代码都不放在根目录。

agent_assistant/
├── README.md        # 项目总说明：定位、技术栈、目录导航、本地启动步骤
├── .gitignore       # 忽略依赖、构建产物、缓存、.env、运行时静态目录
├── docs/            # 需求、架构、数据库、接口、数据流向、目录说明、技术补充
├── prototype/       # 静态 UI 原型，交互与文案的基线，双击 index.html 即可看
├── web/             # 前端工程，生产代码在 src/，构建产物 dist/ 不提交
├── server/          # 后端工程，生产代码在 app/，脚本在 scripts/，测试在 tests/
└── deploy/          # 部署物，目前是 MySQL 初始化脚本

各目录什么时候看

目录内容典型场景
docs/需求与设计文档、可视化页面评审需求、查接口契约、对齐状态机、了解图片存储方案
prototype/纯静态原型（HTML + CSS + JS）确认交互细节与文案；UI 与逻辑以原型为准
web/Vue 3 前端工程改页面、改交互、对接接口、调样式
server/FastAPI 后端工程改业务规则、加接口、调数据库、写测试
deploy/建库建表脚本新环境初始化数据库

一次请求的路径

浏览器→ views 页面→ api/index.ts→ request.ts（axios）→ api/v1 路由→ services 领域服务→ repositories→ MySQL
services 头像逻辑→ obs_service→ OBS

5server/ · 后端工程（FastAPI + SQLAlchemy + MySQL）

api 路由层→ services 领域服务→ repositories 数据访问→ models ORM 模型→ MySQL

分层约束：路由层只做参数绑定与调用，不写业务判断；服务层不依赖 HTTP 对象；仓储层只做查询与写入，不写业务规则；模型层只描述表结构。

server/
├── app/                     # 💡【后端核心应用根目录】90% 的业务生产代码都在这里
│   ├── main.py              # 总开关/应用装配：中间件、异常处理、路由注册、/static 挂载
│   ├── api/                 # 💡【接口路由层】接待请求、接收参数、返回结果，不写具体业务判断
│   │   ├── health.py         # 健康检查接口（无 /api/v1 前缀，供探针检测）
│   │   └── v1/              # 业务模块具体 API 路由集合
│   │       ├── assistants.py # 助理相关接口
│   │       ├── shares.py     # 共享相关接口
│   │       └── approvals.py  # 审批相关接口
│   ├── core/                # 💡【基础设施层】配置、数据库连接、鉴权、全局异常等通用底层
│   │   ├── config.py            # 配置中心：读取 .env
│   │   ├── database.py          # Engine、Session、Base 会话管理
│   │   └── security.py          # 安全与鉴权：解析当前用户与管理员身份
│   ├── models/              # 💡【模型层】使用 SQLAlchemy ORM 定义数据库表结构
│   │   ├── base.py              # ORM 基类、抽离公共字段
│   │   ├── assistant.py         # 助理主表及关联组成表
│   │   └── approval.py          # 审批单表模型
│   ├── schemas/             # 💡【契约层】Pydantic 入参出参模型，自动校验请求数据合法性
│   ├── repositories/        # 💡【仓储层/数据访问】专门负责写 SQL 或 ORM 查询写入，不写业务规则
│   │   ├── assistant_repo.py    # 助理查询（三范围 UNION）、写入、软删除
│   │   ├── approval_repo.py     # 审批单查询与状态更新
│   │   └── category_repo.py     # 分类字典读写操作
│   └── services/            # 💡【核心领域服务层/核心大脑】封装所有业务逻辑、状态流转、权限校验等核心规则
│       ├── assistant_service.py  # 助理核心业务：列表/详情/创建/编辑/删除、头像归一化
│       ├── approval_service.py   # 审批中心业务：列表、双视图、通过/拒绝、回写状态
│       ├── share_service.py      # 共享管理业务：提交、回显、调整、下架申请
│       ├── scope_service.py      # 权限范围计算：四维展开（并集-单独移除）、人数校验、授权物化
│       ├── summon_service.py     # 召唤与订阅业务：召唤、订阅移除、重新订阅
│       ├── ai_service.py         # AI 生成业务：大模型调用封装、失败模板兜底逻辑
│       ├── common_service.py     # 通用业务服务：头像校验、写 OBS、URL 转换等
│       └── obs_service.py        # OBS 客户端封装：上传、删除、公网 URL 获取
├── migrations/             # Alembic 数据库迁移配置
├── scripts/                # 运维、迁移、联调、OBS 测试脚本集合
├── certs/                  # 证书目录：OBS 私有根证书
├── static/                 # 本地头像回退目录
├── tests/                  # 基于 pytest 的自动化接口回归测试套件
├── .env                    # 本地真实环境变量（绝对不能提交）
└── requirements.txt        # Python 第三方依赖清单

scripts 脚本分类

类别脚本用途
数据库 check_schema.py、migrate_v100_schema.py 结构校验、存量库升级迁移
数据 seed_dev_data.py、reset_dev_data.py 灌演示数据、重置开发库
端到端联调 e2e_assistant_crud.py、e2e_share_flow.py 对运行中的服务发真实 HTTP 请求验证全链路
对象存储 obs_probe.py、obs_upload.py 连通性探测、批量上传

常用环境变量与启动

变量作用
DATABASE_URLMySQL 连接串（含库名、账号、密码）
LLM_API_KEY / LLM_BASE_URLAI 生成使用的大模型配置
OBS_*对象存储端点、桶、密钥、访问域名

7改动速查：改什么、动哪些文件

要改的事需要动的文件
新增一个接口 api/v1/xxx.py → schemas/ → services/（核心业务）→ web/src/api/index.ts
修改核心业务逻辑 直接定位到 services/ 领域服务层 对应模块进行修改
调整数据库查询 repositories/（数据访问层）

8开发联调规范与常见故障排查（FAQ）

🖼️ 头像上传失败或裂图

检查 OBS_* 配置及私有根证书。若云端不可用，系统会自动降级写入本地 server/static/ 目录。

🤖 AI 自动生成结果为空或固定

当大模型未配置、网络超时或报错时，ai_service.py 会自动平滑降级为内置模板兜底。
