根目录只放 5 个主目录 + 2 个说明文件，任何业务代码都不放在根目录。

各目录什么时候看

目录内容典型场景
docs/需求与设计文档、可视化页面评审需求、查接口契约、对齐状态机、了解图片存储方案
prototype/纯静态原型（HTML + CSS + JS）确认交互细节与文案；UI 与逻辑以原型为准
web/Vue 3 前端工程改页面、改交互、对接接口、调样式
server/FastAPI 后端工程改业务规则、加接口、调数据库、写测试
deploy/建库建表脚本新环境初始化数据库

一次请求的路径

浏览器→ views 页面→ api/index.ts→ request.ts（axios）→ api/v1 路由→ services 领域服务→ repositories→ MySQL
services 头像逻辑→ obs_service→ OBS

5server/ · 后端工程（FastAPI + SQLAlchemy + MySQL）

api 路由层→ services 领域服务→ repositories 数据访问→ models ORM 模型→ MySQL

分层约束：路由层只做参数绑定与调用，不写业务判断；服务层不依赖 HTTP 对象；仓储层只做查询与写入，不写业务规则；模型层只描述表结构。

7改动速查：改什么、动哪些文件

要改的事需要动的文件
新增一个接口 api/v1/xxx.py → schemas/ → services/（必要时 repositories/）→ web/src/api/index.ts → web/src/types/ → docs/03-接口设计.md
新增表或字段 models/ → docs/02-数据库设计.md → deploy/mysql/assistant_mysql.sql → 存量库迁移脚本
调整状态机 / 审批规则 services/approval_service.py、share_service.py、models/assistant.py（CHECK 约束）→ docs/01、docs/02 → 对应测试
改列表卡片 / 详情交互 web/src/components/、views/assistant/；对照 prototype/
接入平台主数据 services/master_data.py（保持函数签名，替换数据源）
