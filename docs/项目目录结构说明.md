# 数智助理 · 助理团 项目目录结构说明

> 本文档描述仓库的整体目录结构与各文件职责，便于新人快速熟悉工程。
> 项目由 4 部分组成：`docs/`（设计与需求）、`prototype/`（静态 UI 原型）、`web/`（前端工程）、`server/`（后端工程），外加 `deploy/`（部署脚本）。

## 一、顶层目录

```
agent_assistant/
├── README.md                项目总说明（导航、目录、技术栈、本地运行）
├── .gitignore               Git 忽略规则
├── docs/                    设计与需求文档（Markdown + 数据流向图）
├── prototype/               UI 原型，纯静态，双击 index.html 即可运行
├── web/                     前端工程（Vue 3 + TypeScript + Vite）
├── server/                  后端工程（Python + FastAPI + MySQL 8.0）
└── deploy/                  部署物（MySQL 建表脚本）
```

---

## 二、docs/ 设计与需求文档

```
docs/
├── 需求说明书.md            13 个功能点、EARS 需求列表、验收标准（V1.17）
├── 01-总体架构设计.md       分层架构、模块划分、关键设计决策、权限模型、状态机、核心链路时序
├── 02-数据库设计.md         ER 图、14 张表 DDL、索引与性能、数据一致性规则
├── 03-接口设计.md           33 个接口清单、出入参、错误码、页面映射
└── data_flow.html           全链路数据流向可视化（原型 → 接口 → 落库）
```

| 文件 | 作用 |
|------|------|
| `需求说明书.md` | 产品需求源头，定义做什么/不做什么、验收标准 |
| `01-总体架构设计.md` | 技术方案总纲：分层规则、权限模型、状态机、时序图 |
| `02-数据库设计.md` | 数据模型与 14 张表结构（后端 models 与建表脚本的依据） |
| `03-接口设计.md` | 33 个 REST 接口的出入参、错误码（前端 api、后端 routes 的依据） |
| `data_flow.html` | 可交互的数据流向图，用于评审 |

## 五、server/ 后端工程（FastAPI + SQLAlchemy + MySQL）

分层约束：`api → services → repositories → models`（路由层不写业务判断，服务层不依赖 HTTP 对象，仓储层不写业务规则）。

```
server/
├── app/
│   ├── main.py              FastAPI 应用装配入口（中间件/路由/静态资源挂载）
│   ├── __init__.py          应用包声明
│   ├── api/                 路由层
│   │   ├── health.py        健康检查路由（不带 /api/v1 前缀，供探针直接访问）
│   │   ├── __init__.py      路由层包声明
│   │   └── v1/              v1 业务路由（对应用户的各个业务域）
│   │       ├── __init__.py    v1 路由汇总注册
│   │       ├── assistants.py  助理路由（接口 1~8）
│   │       ├── shares.py      共享授权路由（接口 19~21）
│   │       ├── approvals.py   共享审批路由（接口 22~27）
```

## 六、deploy/ 部署物

```
deploy/
└── mysql/
    └── assistant_mysql.sql   MySQL 建库建表脚本（14 张表 + 演示数据）
```

| 文件 | 作用 |
|------|------|
| `assistant_mysql.sql` | MySQL 8.0 初始化脚本，执行即建库建表并塞入演示数据 |

> 注意：该脚本会**重建表**，请勿在存量库直接执行；存量库升级用 `server/scripts/migrate_v100_schema.py`。
