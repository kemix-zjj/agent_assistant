三、三个页签的取数规则

我的助理（scope=mine）

固定为「我创建的 custom / thirdparty 助理」，按共享一级状态筛选。
未共享 → share_status = 'unshared' 审批中 → share_status = 'pending' 已共享 → share_status = 'approved' 已拒绝 → share_status = 'rejected' 已下架 → share_status = 'offline'
子类角标由 pending_type / reject_type 渲染。

全部（scope=all）

仅三种状态：平台内置 + 已共享 + 已订阅。
平台内置：assistant.source = 'platform' 已共享（我创建的）： share_status = 'approved' 或 pending AND pending_type IN ('change','scope','offline') 或 rejected AND reject_type != 'share'（含 NULL） 已订阅：assistant_grant.subscribe_status = 'subscribed' AND grant_status = 'valid' AND 创建人 != 我
排除：未共享、审批中 · 共享审批、已拒绝 · 共享审批、已下架。

共享助理（scope=shared）

以授权名册为准，别人创建并授权给我。
assistant_grant.user_id = 当前人员 AND grant_status = 'valid' AND assistant.owner_user_id != 当前账号 订阅筛选：subscribe_status = 'subscribed' / 'removed' 排序：已订阅在前、已移除在后，同状态按 grant_time 倒序

「全部」页签的出参折叠

scope=all 时接口把本质已共享的三类审批中、四类已拒绝统一折叠为「已共享」：
share_status: pending / rejected → approved pending_type / reject_type: → NULL reject_reason / offline_reason: → NULL
只影响接口出参，落库值不变；我的助理页签仍返回真实状态与子类。

核心设计要点：

1. share_scope 是范围申请单，stage 三态（requested / adjusted / effective）记录范围从提交到生效的完整过程，只增不改。

2. share_scope_item 是范围明细，1 张申请单对应 N 行，按 dim（org / role / position / user）存储四维选择。

3. approval 是审批单，记录审批状态流转（pending → approved / rejected / terminated），approval_type 区分 share（共享申请）、scope（授权申请）、change（调整申请）与 offline（下架申请），与助理上的 pending_type / reject_type 一一对应。

4. assistant_grant 是授权名册，只在审批通过或管理员直改时，将 effective 单的维度明细按人展开写入，一人一行，带 grant_status（授权有效性）和 subscribe_status（被授权方订阅状态）两个正交维度。

5. 创建助理不共享时，不写任何共享表，绑定关系由 assistant.owner_user_id 表达；assistant.version 空串表示「未发布」，仅在审批通过时生成或推进（首次记 V1.0.0，此后尾号 +1，到 99 进位）。
